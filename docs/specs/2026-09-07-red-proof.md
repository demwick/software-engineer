# Red-proof and review depth

**Date:** 2026-09-07
**Status:** accepted
**Supersedes:** the "TDD is no longer a rule" paragraph in
`2026-09-04-playbook-architecture.md`

## What changed and why

v5.0.0 removed test-first for new code, classifying it as compensation under
Hard Rule 9. That was a misclassification.

Compensation is something the model would not do on its own and that a model
upgrade absorbs. Preference is a constraint the model cannot infer. Test-first
is preference: the *ordering* is a methodology choice no model derives from the
code, and the ordering changes the artifact. A test written after the code and
a test observed failing before it can be the same file and are not the same
evidence — a test that never failed may not test anything. The user's standing
instruction says so directly (`Test-first: implementation'dan önce failing
test`), which is exactly the class of fact Hard Rule 9 marks durable.

What v5 got right and this spec keeps: the *enforcement* v4 used was
compensation. Commit-order forensics, red-proof replay as a separate script,
the verification-strategy resolver and the `[[ NO-TEST ]]` marker were
machinery around a rule, and the marker in particular became an escape hatch —
a task could declare itself exempt. None of that comes back.

What comes back is the rule plus one measurable property, checked by the agent
that did not write the code.

## Scope

**New behaviour** — a new or changed code path a test can observe. Test-first
applies here.

Out of scope: refactors with no behavioural change, renames, formatting,
configuration, documentation, type-only changes, dependency bumps.

Bug fixes are already covered and unchanged: the reproduction test is committed
alone first, `.se/.fixing` locks it, `pre-guard` blocks a `fix(` commit that
stages its own test.

**The scope decision does not belong to the executor.** v4 let the agent mark a
task exempt and the mark became a rubber stamp. Here the judgement is made
against the diff, by the verifier, after the fact.

## Division of labour

```
red-proof.sh                    verifier
────────────                    ────────
MECHANICAL                      JUDGEMENT
reverts source, runs each       decides which task changed behaviour
Check, reports red/green        (from the diff) and therefore which
                                green result is a finding

decides nothing                 measures nothing
```

A `[GREEN]` from the script is a finding *candidate*. A task whose diff only
touched comments is expected to stay green; a task that added an endpoint and
stayed green has a criterion with no real coverage.

## `scripts/red-proof.sh`

```bash
bash red-proof.sh [project-dir] <id>
```

**Inputs.** `.se/plans/<id>.md` — the `- Check:` line of each `### Task`. Git —
the slice's range, based at the commit whose subject is `docs(se): plan <id>`.

**Sequence.**

1. Refuse a dirty working tree (exit 2). After a finished slice the tree is
   clean, so there is nothing to lose; before one, reverting would destroy
   uncommitted work.
2. Resolve the base commit (exit 3 if absent).
3. Split the slice's changed files into test and source. Test paths match
   `tests?/`, `__tests__/`, `spec/`, `*_test.go`, `*.test.*`, `*.spec.*`,
   `test_*.py`, `conftest.py`. Everything else is source.
4. Restore source files to the base commit. Files the slice added are removed.
   **Test files are never touched.**
5. Run each `Check` command, bounded by `timeout` when it is on PATH.
6. Restore, via `trap … EXIT` so it happens on error, on a failed check, and on
   an interrupt.

**Output.**

```
red-proof: phase-3
BASE: a1b2c3d (docs(se): plan phase-3)
REVERTED: 3 source files (2 test files untouched)
[red]   task 1 — pytest tests/test_users.py::test_delete_returns_204
[GREEN] task 2 — pytest tests/test_users.py::test_list_pagination
NOTE: the slice changed no test file
SUMMARY: 2 checks, 1 red, 1 green
```

`[red]` is the expected result: with the source gone the test fails, so it
exercises the change. `[GREEN]` is uppercase because it is the line to read.

**Exit codes.** `0` ran · `1` no plan or no `Check` lines · `2` dirty tree ·
`3` base unresolved.

**Ceilings, named.**

- Languages that keep tests inside the source file (Rust `#[cfg(test)]`) cannot
  be separated: reverting the source reverts the test. The script emits the
  `NOTE` line rather than a false `[GREEN]`, and the verifier judges it.
- Without `timeout` on PATH a Check runs unbounded. The full `auto-qa` watchdog
  is not duplicated here: the executor already ran this exact command during
  the slice, so it terminates.
- A `Check` that is the whole suite makes this expensive. That is a defect in
  the plan, not in this script.

## Agent changes

**`agents/executor.md`** — one rule: new behaviour starts with a test that is
run and observed failing, then the code. No turn cost; this reorders work that
already happens. `maxTurns` stays 30.

Cut: the paragraph explaining why to prefer Write/Edit over `sed`. `pre-guard`
gates shell writes identically, so the prose is redundant with the mechanism.

**`agents/verifier.md`** — checks 7 and 8, and a coverage line.

7. **Red proof.** Run `red-proof.sh <id>`, read the result against the diff.
   A `[GREEN]` on a task that changed behaviour is **major**: the criterion has
   no coverage that can fail. A `[GREEN]` on a task that changed no behaviour
   is not a finding.
   A non-zero exit is reported, never silently skipped: `2` (dirty tree) means
   the executor left work uncommitted — that is itself a finding against the
   slice; `1` and `3` are recorded as `red-proof: not run (<reason>)` in the
   report and the coverage line, and do not by themselves fail the verdict.

8. **Liveness.** Is the changed code reached from a real entry point? Grep the
   changed symbols, then grep them as strings for dynamic dispatch. Dead code
   that looks live is how a slice passes every test while changing nothing that
   runs.

```
COVERAGE: <N> files read; <N> commits reviewed; <N> checks red-proofed
          (<N> green); <N> touchpoints traced; criteria <met>/<total>
```

A verdict without that line is not a verdict. It is a wire format, not
persuasion: it turns "I looked" into a number that can be disputed.

Cut: the claim that the Stop hook parses the final `{"ok": …}` line. `auto-qa`
does not read it; the flow's Act step does.

`maxTurns` 12 → 16. Tools unchanged — `Read, Glob, Grep, Bash` already covers a
script call and greps.

`.review.json` gains no fields. The coverage line lives in the human report; a
schema change would need a consumer and there is none yet.

## Out of scope

Considered and deliberately excluded:

- **RECONCILE** (verify the plan still holds against HEAD before writing code).
  Costs executor turns; its value is highest across long gaps, which is not the
  common case here.
- **Passing the executor's `NOTES:` into the verifier's prompt.** The verifier
  still receives only the slice id.
- **Per-criterion mutation** beyond the single revert per Check.
- **A temporary worktree** for the revert. Better isolation, but a fresh
  worktree has no installed dependencies, so a Check would fail for the wrong
  reason and produce false findings.

## Acceptance criteria

- [ ] `red-proof.sh` exits 2 on a dirty working tree and changes no file.
- [ ] With a fixture slice whose task 1 is covered and task 2 is not, the
      output carries exactly one `[red]` and one `[GREEN]`.
- [ ] After any exit path — success, failed check, or interrupt — `git status`
      is clean and every source file matches HEAD.
- [ ] Test files are byte-identical before and after a run.
- [ ] `prompt-quality.sh` fails when the executor loses the test-first rule, or
      the verifier loses `red-proof.sh`, liveness, or `COVERAGE:`.
- [ ] Total instruction text stays under the 48 KB gate.
- [ ] `bash evals/run.sh` is green.

## Trade-offs

**Chosen:** a script for the mechanical half, the agent for judgement.

Accepting: one more file in `scripts/`, and a revert that touches the working
tree. The clean-tree refusal plus `trap` restore is what makes that acceptable;
without both, this design would be worse than the prose rule it replaces.

Rejected: having the executor record its own red observation and the verifier
read it. Zero cost, but self-certification — the model can write a plausible
line without having run anything. The whole reason this rule was worth
restoring is that it can be checked.
